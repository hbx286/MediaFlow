## 6. 文档与基线变更规则

1. **一般修改：** 错字、表述澄清且不改变设计语义时，直接修订当前文件并由 Git 留痕。
2. **设计变更：** 更改状态、字段契约、事务语义、接口或不变量时，创建变更记录并标出受影响文档和测试。
3. **版本升级：** 设计发生不兼容变化或需要单独保留设计快照时，创建新文档版本（例如 `V1.1.md`）。
4. **基线变更：** 已批准基线不应被静默替换。为新一轮开发创建新基线编号，列出准确版本及 Git Commit。
5. **冲突处理：** 不允许根据文件名、编写日期或文档排序自动判断哪份规范优先。发生矛盾时先记录问题、明确所有者、形成决策并同步有关文档。
6. **实现追踪：** 核心开发任务及 PR 应注明基线编号，并关联需求、设计章节和验收测试。
