# MediaFlow 数据库与持久化设计 v1.1 — 执行协议整合增量

> 状态：**候选增量（未经 Migration 执行）**；日期：2026-10-20。  
> **阅读方式：** 本文件与 `Database/V1.0.md` 共同构成候选数据库设计，凡执行协议内容冲突，以本文件和 `Execution/V1.0.md` 为准。不是完整可执行 Migration；不要直接对线上库执行以下 SQL 片段。  
> 变更目的：统一 Workflow/Scheduler/Worker 对 Task、依赖决议、资源预留、结果确认、外部 Job 的数据库要求。原 v1.0 保留。

## 1. 变更台账

| 对象 | v1.0 问题 | v1.1 定案 | 级别 |
|---|---|---|---|
| `tasks` | 缺少逻辑任务去重 | `logical_task_key` 非空，`UNIQUE(node_run_id,logical_task_key)` | P0 |
| `workflow_runs` | 缺暂停/取消意图 | `pause_requested_at,cancel_requested_at` | P0 |
| `node_dependency_satisfactions` | 只记录满足，无法表达未选中/不可满足；可能跨 Run | 迁移为 `node_dependency_decisions`，组合 FK 约束同 Run | P0 |
| 动态展开 | 仅靠 expansion_key 不保证来源决议 | 增加 `node_expansions`，唯一 `(parent_node_run_id, expansion_key)` | P0 |
| `task_attempts` | 重复提交状态不独立 | 增加 `attempt_result_submissions` | P0 |
| staging 对象 | 上传和结果提交不能跨系统事务 | 增加 `staged_artifacts`，确认/回收状态 | P0 |
| Provider async job | 远端任务无法追踪 | `external_model_jobs` 唯一 Provider Job 身份 | P1 |
| 资源预留 | v1.0 仅描述草案，Scheduler 又定义 `scheduler_reservations` | **只使用** `resource_reservations` + `resource_pool_counters` | P0 |
| Worker Session | `EXPIRED` 与协议 `LOST` 用词差异 | 数据库沿用 `EXPIRED`；API 以 LOST 为呈现标签，不增加重复 DB 状态 | P1 |
| `tasks` → `task_attempts` 环形 FK | 建表顺序需受控 | Migration 创建 tasks、attempts 后 ALTER 加当前 Attempt FK | P0 |
| `QUEUED` | 多处视为必经态 | 不强制必经；`READY→RUNNING` 原子 Claim 合法 | P0 |

## 2. 强一致模型的最终表清单

**工作流：** `workflow_runs`, `node_runs`, `node_dependency_decisions`, `node_expansions`。  
**执行：** `tasks`, `task_attempts`, `attempt_result_submissions`。  
**调度：** `worker_sessions`, `resource_pools`, `resource_pool_counters`, `resource_reservations`, `quota_accounts`。  
**资产：** v1.0 `assets`, `asset_versions`, `asset_ingestions`, `asset_references` + 新增 `staged_artifacts`。  
**远端任务：** `external_model_jobs`。  
**可靠性：** `outbox_events`, `inbox_receipts`, `idempotency_records`。

### 2.1 状态与版本字段

- 每个可变聚合根保留 `lock_version bigint NOT NULL DEFAULT 0`，CAS 用 `UPDATE ... SET lock_version=lock_version+1 WHERE id=$1 AND lock_version=$expected`。
- `lease_epoch bigint` 是 Task 执行代数，永不因重新入队而减少。新的 Claim 单调 +1。
- 已发布 WorkflowVersion/AssetVersion 不可变，禁止直接覆盖。
- `attempt_no` 为同一 Task 的执行序号，与 `lease_epoch` 分别保留；同一 Claim 可以同步增加两者，但语义不能混同。

## 3. PostgreSQL DDL 修订草案

下面语句适用于**新数据库逻辑建模参考**。已有数据升级需先进行非空字段回填和约束验证；表重命名、合并和删除必须有独立迁移方案。

### 3.1 已有表增量

```sql
-- 对已有库的逻辑升级示意：先填充历史数据，再 SET NOT NULL。
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS logical_task_key text;
CREATE UNIQUE INDEX IF NOT EXISTS ux_tasks_node_logical
  ON tasks(node_run_id,logical_task_key)
  WHERE logical_task_key IS NOT NULL;
-- 验证历史空值为 0 之后：
-- ALTER TABLE tasks ALTER COLUMN logical_task_key SET NOT NULL;

ALTER TABLE tasks ADD COLUMN IF NOT EXISTS deadline_at timestamptz;
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS scheduling_class text NOT NULL DEFAULT 'default';
ALTER TABLE workflow_runs ADD COLUMN IF NOT EXISTS pause_requested_at timestamptz;
ALTER TABLE workflow_runs ADD COLUMN IF NOT EXISTS cancel_requested_at timestamptz;
```

**强约束决策：** 新库应直接对 `tasks.logical_task_key` 设 `NOT NULL` 和普通唯一索引；上面的部分索引仅为存量升级过渡，正式冻结后不得长期依赖 NULL 逃过唯一性。

### 3.2 依赖决议（替代 satisfaction-only 表）

```sql
CREATE TABLE node_dependency_decisions (
  workflow_run_id uuid NOT NULL REFERENCES workflow_runs(id),
  target_node_run_id uuid NOT NULL,
  dependency_key text NOT NULL CHECK (length(dependency_key) > 0),
  source_node_run_id uuid NOT NULL,
  source_outcome_version bigint NOT NULL CHECK (source_outcome_version >= 0),
  outcome text NOT NULL CHECK (outcome IN ('SATISFIED','NOT_SELECTED','IMPOSSIBLE')),
  decided_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (target_node_run_id, dependency_key),
  FOREIGN KEY (target_node_run_id,workflow_run_id)
    REFERENCES node_runs(id,workflow_run_id),
  FOREIGN KEY (source_node_run_id,workflow_run_id)
    REFERENCES node_runs(id,workflow_run_id)
);
CREATE INDEX ix_dependency_decisions_run ON node_dependency_decisions(workflow_run_id,target_node_run_id);
```

`NOT_SELECTED` 不表示节点失败；`IMPOSSIBLE` 表示该边不能提供必需成功结果。Join/Condition 策略需要读取所有已决议边，并检查未决议边是否仍可能成功。`remaining_dependencies` 可作为派生缓存而非唯一判断依据。存量迁移需将原 satisfaction 行转为 SATISFIED，并对未决议边按 DAG 实例补齐；不能无条件 DROP 原表。

### 3.3 动态展开持久化

```sql
CREATE TABLE node_expansions (
  id uuid PRIMARY KEY,
  workflow_run_id uuid NOT NULL REFERENCES workflow_runs(id),
  parent_node_run_id uuid NOT NULL,
  expansion_key text NOT NULL CHECK (length(expansion_key) > 0),
  source_fingerprint text NOT NULL,
  expansion_spec jsonb NOT NULL,
  status text NOT NULL CHECK (status IN ('PENDING','APPLIED','FAILED')),
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE(parent_node_run_id,expansion_key),
  FOREIGN KEY(parent_node_run_id,workflow_run_id)
    REFERENCES node_runs(id,workflow_run_id)
);
```

重试同一展开命令需校验 `source_fingerprint` 一致；不同内容碰撞则拒绝。已展开子 NodeRun 仍由 `(workflow_run_id,node_definition_id,expansion_key)` 唯一约束保护。

### 3.4 结果提交与暂存对象

```sql
CREATE TABLE attempt_result_submissions (
  id uuid PRIMARY KEY,
  task_id uuid NOT NULL,
  attempt_id uuid NOT NULL,
  submission_key text NOT NULL CHECK (length(submission_key) > 0),
  manifest_hash text NOT NULL,
  status text NOT NULL CHECK(status IN ('RECEIVED','COMMITTED','REJECTED')),
  committed_result_ref jsonb,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE(attempt_id,submission_key),
  FOREIGN KEY(task_id,attempt_id) REFERENCES task_attempts(task_id,id)
);

CREATE TABLE staged_artifacts (
  id uuid PRIMARY KEY,
  attempt_id uuid NOT NULL REFERENCES task_attempts(id),
  storage_key text NOT NULL UNIQUE,
  content_hash text NOT NULL,
  size_bytes bigint NOT NULL CHECK(size_bytes >= 0),
  mime_type text NOT NULL,
  status text NOT NULL CHECK(status IN ('STAGED','VERIFIED','COMMITTED','ORPHANED')),
  asset_version_id uuid REFERENCES asset_versions(id),
  created_at timestamptz NOT NULL DEFAULT now(),
  committed_at timestamptz,
  CHECK ((status = 'COMMITTED') = (asset_version_id IS NOT NULL))
);
CREATE INDEX ix_staged_artifacts_gc ON staged_artifacts(status,created_at)
  WHERE status IN ('STAGED','VERIFIED','ORPHANED');
```

**ResultCommit 不变量：** 相同 `(attempt_id, submission_key)` 且相同 manifest_hash 返回已提交结果；相同键不同摘要必须冲突。Task/Attempt、结果引用、Reservation Release、Outbox 在同一事务确认。AssetVersion 引用只有在稳定对象存在且可校验时才能建立。

### 3.5 资源账本：统一名称

```sql
-- 注意 resource_pools 在 Database v1.0 为逻辑预留；迁移必须先真正创建。
CREATE TABLE resource_pool_counters (
  pool_id uuid PRIMARY KEY REFERENCES resource_pools(id),
  capacity_slots integer NOT NULL CHECK (capacity_slots >= 0),
  reserved_slots integer NOT NULL DEFAULT 0 CHECK (reserved_slots >= 0),
  lock_version bigint NOT NULL DEFAULT 0,
  CHECK (reserved_slots <= capacity_slots)
);

CREATE TABLE resource_reservations (
  id uuid PRIMARY KEY,
  task_id uuid NOT NULL,
  attempt_id uuid NOT NULL,
  worker_session_id uuid NOT NULL REFERENCES worker_sessions(id),
  pool_id uuid NOT NULL REFERENCES resource_pool_counters(pool_id),
  slots integer NOT NULL CHECK (slots > 0),
  status text NOT NULL CHECK(status IN ('ACTIVE','RELEASED')),
  created_at timestamptz NOT NULL DEFAULT now(),
  released_at timestamptz,
  UNIQUE(attempt_id,pool_id),
  FOREIGN KEY(task_id,attempt_id) REFERENCES task_attempts(task_id,id),
  CHECK ((status = 'RELEASED') = (released_at IS NOT NULL))
);
CREATE INDEX ix_reservations_active_pool
  ON resource_reservations(pool_id) WHERE status = 'ACTIVE';
```

资源 Claim 只允许 `reserved_slots + requested_slots <= capacity_slots` 时进行，释放时必须依赖 Reservation 从 ACTIVE→RELEASED 的成功条件更新，确保**只释放一次**。多池预留必须按 `pool_id` 稳定顺序锁定。CPU/内存/GPU 等多维真实资源需要独立维度账本或资源向量受锁校验；以上 `slots` 是第一条执行链路的明确最小契约，**不可声称已经覆盖多资源调度**。

### 3.6 异步供应商任务

```sql
CREATE TABLE external_model_jobs (
  id uuid PRIMARY KEY,
  task_id uuid NOT NULL REFERENCES tasks(id),
  submit_attempt_id uuid NOT NULL REFERENCES task_attempts(id),
  provider_configuration_id uuid NOT NULL REFERENCES provider_configurations(id),
  external_job_id text,
  submission_key text NOT NULL,
  status text NOT NULL CHECK(status IN
    ('SUBMITTED','PROCESSING','SUCCEEDED','FAILED','CANCELED','UNKNOWN')),
  input_fingerprint text NOT NULL,
  result_ref jsonb,
  last_polled_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE(provider_configuration_id,submission_key)
);
CREATE UNIQUE INDEX ux_external_job_identity ON external_model_jobs(provider_configuration_id,external_job_id)
  WHERE external_job_id IS NOT NULL;
```

这是**状态存储基线**而非完整异步 Job 编排协议。回调/轮询如何触发合法 TaskAttempt/ResultCommit 必须在 Worker/API 详细实现前审定，不能凭外部成功响应直接将内部 Task 标为 SUCCEEDED。

## 4. 核心事务与锁序（规范性）

| 事务 | 写入的权威对象 | 必须一起提交 | 禁止事项 |
|---|---|---|---|
| `StartWorkflow` | WorkflowRun/NodeRun/Outbox | 版本、输入快照、初始就绪状态 | 跨事务只建 Run 不建必要初始节点 |
| `ResolveDependency` | DependencyDecision/NodeRun/Task/Outbox | 边决议与唯一逻辑任务创建 | 重复事件无条件递减依赖计数 |
| `ClaimAndReserve` | Task/Attempt/Reservation/PoolCounter/Outbox | 当前 Attempt+epoch+资源扣减 | 在事务中执行网络 IO |
| `RenewLease` | TaskAttempt | 授权校验 + 单调延期 | 仅凭 worker_id 续租 |
| `ResultCommit` | Submission/Task/Attempt/AssetVersion/Reservation/Counter/Outbox | 有效结果与资源释放 | 上传对象后未校验就写 SUCCEEDED |
| `RecoverExpiredAttempt` | Task/Attempt/Reservation/Counter/Outbox | 旧授权失效 + 释放 + 重试决定 | 未终结旧 Attempt 就创建新活跃 Attempt |
| `ProgressWorkflow` | NodeRun/DependencyDecision/WorkflowRun/Outbox/Inbox | 节点成功确认与去重传播 | 将 Task Success 等同 Run Success |

**初步锁序**：WorkflowRun/必要执行许可 → Task → TaskAttempt → 按 ID 排序的 ResourcePoolCounter → 配额记录 → ResultSubmission/资产引用；`NodeRun` 进度事务单独处理并按 NodeRun ID 稳定锁序。此锁序属于**待 SQL 审查的约定**：不可一边 Claim 先持有 Task 再等待 Run，另一边 Cancel 先锁 Run 再等待 Task。确切查询、取消扫描与分页边界须在集成测试中冻结。

`READ COMMITTED` + 必要行锁和 CAS 可以作为初始方案；需要明确所有不变量锁保护的具体行。不可以依赖隔离级别名称替代并发测试。事务发生 `40P01` 死锁或 `40001` 序列化冲突时按幂等业务操作重新启动事务并进行退避。

## 5. 不变量与验证位置

| 不变量 | PostgreSQL 约束 | 事务/应用校验 |
|---|---|---|
| 一个逻辑 Task 不重复创建 | `UNIQUE(node_run_id,logical_task_key)` | 冲突时比对任务定义摘要 |
| 同一 Task 一个活跃 Attempt | 部分唯一索引 `task_attempts(task_id) WHERE status IN (...)` | Claim 先结束旧 Attempt，验证 epoch |
| Attempt 属于对应 Task | 组合 FK `(task_id,attempt_id)` | 结果提交校验 current_attempt_id |
| 同 Run 依赖边 | 组合 FK `(node_id,workflow_run_id)` | DAG 语义、Join 判定 |
| 同一边最多一次决议 | `PRIMARY KEY(target_node_run_id,dependency_key)` | 重复 payload 逐字段比对 |
| 资源不超售 | `CHECK(reserved_slots<=capacity_slots)` | 条件 UPDATE + 行锁 |
| 资源只释放一次 | 唯一 `(attempt_id,pool_id)` | `UPDATE ... WHERE status='ACTIVE' RETURNING` |
| 有效结果唯一 | `(attempt_id,submission_key)` 去重 | Task/Attempt/epoch/token/session/expiry + 摘要校验 |
| AssetVersion 不可变 | 写权限/触发器（待迁移实现） | 对象完整性校验与引用一致性 |
| 租户归属有效 | FK + 组合 FK（需迁移扩展） | 业务访问权限 + 测试覆盖 |
